Spring Boot + Netty 使用流程 (deepblue.inaction_02_springboot)

一、案例是什么
	- 一个 IM / 推送服务: Spring Boot 负责 HTTP 接口、配置、Bean 管理和生命周期; Netty 另开一个 TCP 端口, 负责客户端长连接。
	- 端口: HTTP 8080 (server.port), TCP 9000 (netty.server.port)。
	- 能力:
	    · 客户端 LOGIN 登录, 服务端绑定 userId ⇄ Channel;
	    · 客户端之间点对点聊天 (CHAT), 对方不在线时返回 ERROR;
	    · 心跳: 客户端写空闲 20s 发 PING, 服务端回 PONG; 服务端读空闲 60s 踢掉连接;
	    · 断线重连: 客户端按 1s, 2s, 4s ... 最多 30s 指数退避重连;
	    · 重复登录: 同一个 userId 再次登录时, 旧连接先收到 KICKED 再被关闭, 旧客户端不再重连;
	    · HTTP → TCP: 其它系统调 HTTP 接口, 服务端经 Netty 长连接主动推送给客户端 (PUSH)。
	- 协议: 一行一个 JSON, 以 \n 结尾 (行协议是为了方便 telnet / nc 调试; 生产中的二进制协议换成 LengthFieldBasedFrameDecoder)。
	    {"type":"LOGIN","from":"tom"}
	    {"type":"CHAT","from":"tom","to":"jerry","content":"hi"}
	    {"type":"PING","from":"tom"}
	- 消息类型 (model/MessageType):
	    LOGIN     客户端 → 服务端  登录
	    LOGIN_OK  服务端 → 客户端  登录成功
	    PING      客户端 → 服务端  心跳
	    PONG      服务端 → 客户端  心跳响应
	    CHAT      客户端 → 服务端 → 目标客户端  点对点聊天
	    PUSH      服务端 → 客户端  HTTP 接口触发的主动推送
	    ERROR     服务端 → 客户端  错误提示 (未登录、对方离线、类型不支持等)
	    KICKED    服务端 → 客户端  同一个 userId 在别处登录, 被踢下线; 客户端收到后不再重连


二、目录结构
	inaction_02_springboot
	├── config
	│   └── NettyServerConfig              @ConfigurationProperties("netty.server"): 端口、线程数、读空闲时间、最大帧长度、高低水位
	├── server
	│   ├── NettyServer                    实现 SmartLifecycle: Spring 容器启动完成后 bind 端口, 容器关闭时优雅停机
	│   └── NettyServerInitializer         服务端每个连接的 Pipeline 组装
	├── handler
	│   ├── inbound
	│   │   ├── JsonMessageDecoder         String → Message (@Sharable Spring 单例)
	│   │   ├── ServerBusinessHandler      服务端业务: LOGIN / PING / CHAT, 读空闲踢人, 兜底异常 (@Sharable Spring 单例)
	│   │   └── ClientHandler              客户端: 打印消息、写空闲发心跳、断线回调重连, 被踢下线时不重连 (非 Spring Bean)
	│   └── outbound
	│       └── JsonMessageEncoder         Message → 一行 JSON (@Sharable Spring 单例)
	├── session
	│   └── ChannelSessionManager          userId ⇄ Channel; 重复登录下发 KICKED 并关闭旧连接; 写之前检查 isWritable; Spring 和 Netty 之间的桥
	├── controller
	│   └── NettyPushController            GET /netty/online, POST /netty/push, POST /netty/broadcast
	├── model
	│   ├── Message                        type / from / to / content
	│   └── MessageType                    消息类型枚举
	└── client
	    ├── MineNettyClient                独立 main 客户端 (不依赖 Spring), 控制台输入 "<to> <content>" 发消息
	    └── NettyClientInitializer         客户端 Pipeline 组装, 与服务端对称

	相关文件:
	    src/main/resources/application.properties        netty.server.* 配置
	    src/test/java/deepblue/NettyAdvancedApplicationTest  集成测试


三、整体流程
	1. 启动:
	    NettyAdvancedApplication.main
	    → Spring 创建 Bean: NettyServerConfig、JsonMessageDecoder、JsonMessageEncoder、ServerBusinessHandler、ChannelSessionManager ...
	    → Tomcat 启动 (8080)
	    → 容器刷新完成, 调用 NettyServer.start():
	        创建 bossGroup (accept) / workerGroup (IO) / bizGroup (业务)
	        → ServerBootstrap 配置参数和 NettyServerInitializer → bind(9000)

	2. 客户端连接:
	    accept → 新 Channel 注册到某个 worker EventLoop → NettyServerInitializer.initChannel() 组装 Pipeline:

	    Head
	     → IdleStateHandler(60s 读空闲)                    每个连接 new (有状态)
	     → LineBasedFrameDecoder(8192)                     每个连接 new (有状态), 按 \n 切帧
	     → StringDecoder                                   ByteBuf → String
	     → JsonMessageDecoder                              String → Message (单例)
	     → StringEncoder                                   String → ByteBuf (出站)
	     → JsonMessageEncoder                              Message → String (出站, 单例)
	     → [bizGroup] ServerBusinessHandler                业务 (单例, 跑在业务线程池)
	    Tail

	3. 入站 (客户端 → 服务端):
	    Socket 字节 → 切帧 → String → Message → ServerBusinessHandler.channelRead0
	      · LOGIN: sessionManager.bind(userId, channel), 回 LOGIN_OK;
	               该 userId 已有旧连接时, 给旧连接写 KICKED, 写完后关闭 (ChannelFutureListener.CLOSE)
	      · PING : 回 PONG
	      · CHAT : 查 sessionManager 找到目标 Channel, 转发; 不在线回 ERROR

	4. 出站 (服务端 → 客户端):
	    ctx / channel.writeAndFlush(Message) → JsonMessageEncoder → StringEncoder → Head → Socket

	5. HTTP → TCP 推送:
	    curl POST /netty/push (Tomcat 线程)
	    → NettyPushController → ChannelSessionManager.send(userId, msg)
	    → channel.writeAndFlush (非 EventLoop 线程调用时, Netty 自动转成任务交给该 Channel 的 EventLoop, 线程安全)
	    → 客户端收到 PUSH

	6. 断开:
	    客户端关闭 / 读空闲被踢 / 重复登录被踢 → ServerBusinessHandler.channelInactive → sessionManager.unbind(channel)
	    (unbind 用 remove(userId, channel) 只移除自己, 不会误删重复登录后的新连接)
	    客户端侧: 普通断开 → 指数退避重连; 收到过 KICKED 的连接断开 → 不重连

	7. 停机:
	    Spring 容器关闭 → NettyServer.stop(): 关 serverChannel → shutdownGracefully boss → worker → biz


四、和 Spring 结合的关键点
	- 启动时机: 用 SmartLifecycle, 不要在 @PostConstruct 里 bind().sync().channel().closeFuture().sync(),
	  否则 Spring 启动线程被永久阻塞, 后面的 Bean 和 Tomcat 都起不来。
	- Handler 与 Bean: 无状态的 Handler 加 @Sharable 做成 Spring 单例, 可以直接注入 Service / Mapper;
	  有状态的 (IdleStateHandler、FrameDecoder) 每个连接必须 new, 不能做成单例。
	- 线程: 业务 Handler 用 addLast(bizGroup, ...) 放到 DefaultEventExecutorGroup, 查库等阻塞操作不占 IO 线程;
	  同一个 Channel 固定在同一个业务线程上, 事件顺序不变。
	- NettyServerInitializer 不是 Spring Bean: 它依赖的 bizGroup 由 NettyServer 随生命周期创建和关闭, 所以在 start() 中 new。
	- 流量控制: 设置了高低水位, ChannelSessionManager.send 前检查 isWritable(), 对端消费慢时直接拒绝, 防止 OOM。


五、测试流程

	方式一: 自动化测试 (最快, 不占用 8080 / 9000)
	    在项目根目录执行:
	        mvn test
	    或在 IDEA 中运行 src/test/java/deepblue/NettyAdvancedApplicationTest。
	    测试内容: 启动整个 Spring 容器 (HTTP 和 Netty 都用随机端口), 用 java.net.Socket 模拟两个客户端 tom / jerry, 依次验证:
	        ① tom、jerry 登录 → 都收到 LOGIN_OK
	        ② tom 发 PING → 收到 PONG
	        ③ tom 发 CHAT 给 jerry → jerry 收到 from=tom 的 CHAT
	        ④ tom 发 CHAT 给 nobody → tom 收到 ERROR
	        ⑤ GET /netty/online → 包含 tom、jerry
	        ⑥ POST /netty/push?to=jerry → 返回 sent=true, jerry 收到 PUSH
	        ⑦ 两个连接先后以 spike 登录 → 旧连接收到 KICKED 后被关闭, 新连接仍能收到 PUSH
	    预期: Tests run: 2, Failures: 0, Errors: 0

	方式二: 手动联调 (IDEA 中操作)
	    1. 启动服务端:
	        运行 deepblue.NettyAdvancedApplication
	        预期日志: Tomcat started on port 8080 ... Netty server started on port 9000
	        (8080 / 9000 被占用时会启动失败, 先停掉旧进程, 或改 server.port / netty.server.port)

	    2. 启动两个客户端:
	        运行 deepblue.inaction_02_springboot.client.MineNettyClient, Program arguments 填 jerry
	        再复制一个运行配置, Program arguments 填 tom
	        (第二个参数可选, 为服务端 TCP 端口, 默认 9000, 例如: tom 19000)
	        IDEA 中同一个 main 要运行两份, 需在运行配置里勾选 Modify options → Allow multiple instances
	        预期: 两个控制台都打印 << Message(type=LOGIN_OK, ... content=welcome xxx)
	              服务端打印 connected / login: jerry / login: tom

	    3. 点对点聊天: 在 tom 的控制台输入
	        jerry hello from tom
	        预期: jerry 控制台打印 << Message(type=CHAT, from=tom, to=jerry, content=hello from tom)

	    4. 对方离线: 在 tom 的控制台输入
	        nobody hi
	        预期: tom 控制台打印 << Message(type=ERROR, ... content=nobody is offline)

	    5. HTTP 接口 (PowerShell 中用 curl.exe, 因为 curl 是 Invoke-WebRequest 的别名):
	        curl.exe http://localhost:8080/netty/online
	            预期: ["jerry","tom"]
	        curl.exe -X POST "http://localhost:8080/netty/push?to=jerry&content=hi-from-http"
	            预期: {"to":"jerry","sent":true}, jerry 控制台打印 PUSH hi-from-http
	        curl.exe -X POST "http://localhost:8080/netty/broadcast?content=notice"
	            预期: {"sent":2}, tom 和 jerry 都收到 PUSH notice

	    6. 心跳: 两个客户端都不输入, 等待 20s 以上
	        预期: 连接一直保持 (客户端每 20s 自动发 PING, 服务端回 PONG, PONG 不打印), 服务端不会踢人。

	    7. 读空闲踢人: 用一个不发心跳的客户端连上 (例如 telnet 127.0.0.1 9000, 什么都不输入), 等待 60s
	        预期: 服务端打印 reader idle, close: /127.0.0.1:xxxxx, 连接被断开。
	        (Windows 没有 telnet 时: 控制面板 → 启用或关闭 Windows 功能 → Telnet Client)

	    8. 断线重连: 停掉 NettyAdvancedApplication
	        预期: 客户端打印 disconnected, 之后依次 reconnect in 1s / 2s / 4s ...
	        重新启动服务端后, 客户端自动连上并重新 LOGIN, 打印 LOGIN_OK。

	    9. 重复登录: 再启动一个 Program arguments 为 tom 的客户端
	        预期: 旧的 tom 客户端打印
	                  << Message(type=KICKED, from=server, to=null, content=tom logged in elsewhere)
	                  kicked offline, will not reconnect (type quit to exit)
	              旧客户端不再重连; 新的 tom 正常在线, 可以继续聊天、收推送。

	    10. 退出客户端: 在客户端控制台输入 quit。

	方式三: 命令行运行 (不用 IDEA)
	    mvn -q dependency:build-classpath -Dmdep.outputFile=target/cp.txt
	    mvn -q compile
	    然后在 Git Bash 中:
	        CP="target/classes;$(cat target/cp.txt)"
	        java -cp "$CP" deepblue.NettyAdvancedApplication
	        java -cp "$CP" deepblue.inaction_02_springboot.client.MineNettyClient jerry
	        java -cp "$CP" deepblue.inaction_02_springboot.client.MineNettyClient tom
	    后续操作同方式二的第 3 ~ 10 步。
